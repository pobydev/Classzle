## 다른 담당과의 약속

- 본문 영역은 `flex-1 min-h-0 overflow-auto`인 `main`입니다.
- 제목 바 높이는 CSS 변수 `--shell-top: 34px`입니다.
- `page.tsx`가 `Step3Dashboard`에 `onBoardActiveChange`를 넘깁니다. 아직 그 prop이 없는 브랜치에서도 타입 오류가 나지 않도록 객체를 펼쳐서 넘깁니다. 합친 뒤에는 그대로 두어도 타입 검사를 받습니다.
- 값이 true이고 3단계이면 사이드바를 56px로 접습니다. 다른 단계로 가면 펼칩니다. `Step3Dashboard`가 사라지면서 false를 보내지 않아도 펼쳐집니다.
- 접힌 줄에는 1~3단계, 저장된 작업, 작업 저장, 사용 가이드가 있고, 새 버전 알림이 있으면 점이 달린 아이콘이 나옵니다. 누르면 펼쳐집니다.
- `Step1Setup`과 `Step2Constraints`의 `confirm`, `alert`, `confirmDialog`는 바꾸지 않았습니다. 다음 담당이 `useConfirm()`으로 바꾸고, 마지막 호출이 사라지면 `main/background.ts`의 `confirm-dialog`를 지웁니다.

```tsx
const confirm = useConfirm();
if (await confirm({ title: '지울까요?', description: '되돌릴 수 없습니다.', confirmLabel: '삭제', danger: true })) { ... }
```

- **메뉴는 Radix 세로 탭으로 두었습니다.** 키보드 조작이 그대로 되고, 안 보이는 단계는 지금처럼 화면에서 빠집니다.

- **통일 문구**는 새 버전 확인이 되는 설치본에서만 전체가 보입니다. 웹과 개발 모드에는 앞 문장만 나옵니다.

# 양식과 생활지도 읽기

- **양식의 드롭다운과 색:** 100행까지이던 것을 1000행까지 넓혔습니다(`TEMPLATE_LAST_ROW`, 양식 A와 B). 받은 양식을 그대로 읽어도 빈 행이 학생이 되지 않는 것을 시험합니다.
- **읽지 못한 생활지도:** 빈칸, `해당없음`, `없음`, `-`, `NONE`이 아닌데 읽지 못한 값은 해당없음으로 넣고 이름과 함께 알립니다.
- **숫자 판정:** `행동(-2)` 자체는 맞게 읽혔지만, `includes('3')` 때문에 `행동(-2) 3월 전입`은 -3으로, `행동(-12)`는 -2로 잘못 읽혔습니다. 이제 유형 낱말 바로 뒤의 첫 숫자만 등급으로 봅니다.
- **달라진 동작:** 등급이 없는 `행동`, `리더`는 조용히 가장 낮은 등급이 되던 것을 해당없음과 안내로 바꿨습니다. 등급을 짐작하지 않습니다. 예전 파일의 `리더(-2)`, `행동(+1)`은 계속 같은 등급으로 읽습니다.
- **표현:** 학생 표의 머리글과 양식 안내의 `생활지도 점수`를 `생활지도`로 바꿨습니다. `Step3Dashboard.tsx`의 통계 표 머리글은 통계 표 담당 몫이라 그대로입니다.
- **시험:** `tests/excelTemplate.test.ts`. 양식을 저장했다가 다시 읽어 확인합니다. 실제 엑셀 프로그램에서 드롭다운을 눌러 보지는 않았습니다.

# 생활지도 입력

담당자가 담임의 명렬표를 보며 혼자 입력하던 일을 줄입니다. 학생당 값은 하나이고, 행동과 정서가 둘 다 있으면 정도를 감안해 하나만 고릅니다(사용자 결정).

## 앱 안 빠른 입력

- 학생 표의 생활지도 칸에서 `수정`, `완료` 없이 값을 한 번 누르면 들어갑니다. 다시 누르면 해제합니다.
- 키보드: 숫자 1~8을 누르면 값이 들어가고 다음 학생으로 갑니다. 0은 해제, 위아래 화살표와 Enter는 이동입니다.
- 탭마다 `입력 N`을 보여 주고, 입력을 시작한 뒤 하나도 없는 반은 기호와 글자로 알립니다. `생활지도 있는 학생만` 스위치가 있습니다.
- 이름, 전학년도, 성별, 성적은 `수정`, `완료` 방식 그대로입니다. 줄을 `memo`로 나눠 값을 바꾼 줄만 다시 그립니다.
- 표의 점수 칸과 유형 칸은 입력 칸 하나로 합쳤습니다.

재 본 값: 학생 30명에 입력 키 30번과 반 옮기기 등 2번입니다. 예전 방식은 값이 있는 학생마다 수정, 목록 열기, 값 고르기, 완료의 4번이었습니다. 330명 표에서 값 하나를 넣는 데 약 24ms입니다.

## 반별 입력표 (선택)

- **내보내기:** 폴더를 고르면 반마다 파일을 만듭니다. 학년, 반, 번호, 이름, 성별, 생활지도 드롭다운만 있고 성적, 다른 반, 메모, 지금 값은 넣지 않습니다. 작성자 속성은 비웁니다. 같은 이름의 파일이 있으면 덮어쓰기 전에 묻습니다.
- **받기:** 여러 파일을 한꺼번에 넣습니다. 전학년도 학년, 반, 번호, 이름이 모두 맞는 줄의 생활지도만 반영합니다. 반영 전에 반별 인원, 바뀌는 학생, 못 맞춘 줄, 읽지 못한 값을 앱 안의 창으로 보여 줍니다.

### 판단한 것

- **지금 값을 파일에 넣지 않고, 빈칸은 '바꾸지 않음'입니다.** 담당자가 먼저 넣은 값을 담임의 빈칸이 지우지 않게 하고, 파일로 나가는 정보를 줄입니다. 값을 지우려면 `해당없음`을 고릅니다.
- **같은 반 파일이 둘이면 그 반은 어느 쪽도 반영하지 않습니다.** 어느 파일이 맞는지 짐작하지 않습니다.
- **한 파일에 같은 학생이 두 번 있으면 앞의 줄만 씁니다.** 뒤의 줄은 못 맞춘 줄로 알립니다.

- **셀 잠금은 넣지 않았습니다.** 이름을 고치면 못 맞춘 줄로 알려 주므로 안전하고, 잠금은 담임의 다른 작업을 방해할 수 있습니다.

## 독립 검토 항목

고치기 전에 재현하고, 앱 수준 항목은 같은 스크립트를 고친 뒤에 다시 돌렸습니다. 항목 30은 재현되지 않아 고치지 않았습니다. Electron은 `navigateOnDragDrop`이 기본으로 꺼져 있어 파일을 떨궈도 화면이 바뀌지 않습니다. 항목 19는 정한 대로 그대로 두었습니다.

- **시험:** 단위 시험은 `tests/projectFiles`, `projectFile`, `studentRemoval`, `reportHtml`, `printFiles`, `mainSafety`, `reviewFixes`, `assignmentMessages`, `studentInput`, `store`, `excel`입니다. 앱 전체로 봐야 하는 것은 `npm run test:review`(`scripts/review-smoke.mjs`)입니다.
- **쓸 수 없는 이름:** `\ / : * ? " < > |`와 윈도우 예약 이름입니다. 이미 있는 파일은 계속 열 수 있도록 읽기와 지우기는 폴더 밖과 숨은 영역만 막습니다.
- **생활지도 읽기:** 유형 낱말이 하나이고 그 바로 뒤에 등급이 있을 때만 읽습니다. 앞뒤 메모는 괜찮습니다(`행동(-2) 3월 전입`, `2학년 정서(-1)`). `행동 2회`나 유형 낱말이 둘인 값은 읽지 않고 알립니다.
- **임시 파일:** 인쇄 파일은 임시 폴더의 `classzle-print`에 둡니다. 켤 때 그 폴더와 전 버전이 남긴 `report-<13자리 숫자>.html|pdf` 가운데 1시간이 지난 것을 지웁니다.
- **되돌리기:** 입력표 반영을 기록합니다. 번호 방식은 표시 설정이라 넣지 않았고, 1단계 표에서 직접 고친 값과 조건은 예전처럼 되돌리기에 들어가지 않습니다.
- **`계` 줄:** 전출 뒤 기준입니다. 전출이 있으면 이름 칸에 `전출 N명 제외`를 적습니다. 전출 예정 학생뿐인 반은 평균을 비웁니다.

## 검증에서 나온 수정

- **옛 저장 파일:** v1.2.4는 읽지 못한 성적을 `null`로 저장했습니다. 파일 전체를 거부하던 것을 고쳐, 엑셀과 같은 규칙으로 500점을 넣고 이름을 알립니다. 없는 값은 채우고 반 표기와 숫자로 저장된 고정 반은 맞춥니다.

- **입력표 되돌리기:** 입력표가 바꾼 학생만 되돌립니다. 그 뒤에 표에서 직접 고친 학생은 직접 고친 값을 둡니다.
